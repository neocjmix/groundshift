# M1: local native reconstruction

The first reconstruction trained on this Mac's **Apple M2 / Metal** using Brush
0.3.0 and 40 real images from the Nerfstudio dozer dataset. It exported a
194,789-Gaussian PLY in an 80.35-second local job. Camera poses in this run were
**obtained from the dataset**, not estimated anew. Initialization also uses the dataset's measured sparse SfM points from the full capture; this is not a photos-only reconstruction. See the [provenance audit and fresh native rerun](RECONSTRUCTION_PROOF.md). Independent CPU pose estimation
is documented in [COLMAP.md](COLMAP.md); keep its registration result separate.

The reconstructed excavator, cones and street were subsequently inspected in the
browser; detailed acceptance is recorded in [VALIDATION.md](VALIDATION.md). A successful
native job deliberately writes `browserRendering: "NOT RUN"`; exporting PLY does
not prove that the browser displayed it.

## Install and run

From the repository root, using native arm64 Python 3.12 or newer:

```sh
python3 scripts/install-brush.py
python3 -m venv data/tools/venv
data/tools/venv/bin/python -m pip install numpy==2.5.4 opencv-python-headless==5.0.0.93
data/tools/venv/bin/python scripts/fetch-reconstruction-sample.py
python3 scripts/reconstruct.py data/datasets/dozer-small data/jobs/dozer-1500 \
  --steps 1500 --resolution 512 --max-splats 200000 \
  --publish public/worlds/reconstructed
npm run dev
```

Load `/worlds/reconstructed/world.json` in the viewer's manifest URL field (or open
`/?world=/worlds/reconstructed/world.json`). The world folder can also be opened
using the viewer's local-folder input. Use a **new output and publication folder**
for another run; scripts refuse to overwrite prior results. Downloaded source
images, native tools, caches and large outputs are ignored by Git.

The installer downloads the official 41,447,012-byte Apple Silicon release archive,
checks its pinned SHA-256, and extracts locally; no Rust, Xcode, Homebrew install,
account or background service is needed. Archive SHA-256:
`65b2631398c839be3c1d4d7160fe2326389dec87830aac0710985e6690a1048c`.
Python packages are isolated in `data/tools/venv`. The core reconstruction adapter
uses only Python's standard library and the downloaded native executable.

## Dataset and license

The dozer scene is outdoor imagery from the Nerfstudio dataset, authored by the
Nerfstudio team and contributors. Its official downloader identifies the
[original Google Drive archive](https://drive.google.com/file/d/1jQJPz5PhzTH--LOcCxvfzV_SDLEp1de3/view).
Groundshift acquires the same dataset through the
[NerfBaselines distribution](https://huggingface.co/datasets/nerfbaselines/nerfbaselines-data/tree/6a638951a007c8b47eb8a0301d48b04d18e955cf/nerfstudio),
which supplies a dataset-level
[Apache-2.0 LICENSE](https://huggingface.co/datasets/nerfbaselines/nerfbaselines-data/blob/6a638951a007c8b47eb8a0301d48b04d18e955cf/nerfstudio/LICENSE).
This is the license of that data distribution, not an assumption based on the
Nerfstudio software license. A local copy is saved with the input and exported
artifact as `SOURCE_LICENSE`.

Acquisition is pinned to revision
`6a638951a007c8b47eb8a0301d48b04d18e955cf`. HTTP byte ranges retrieve 40 evenly
spaced supplied views from `images_4`, the camera metadata, and COLMAP sparse
points. The 1.35 GB archive and its 823 MB feature database are not downloaded in
full. Every extracted member is checked against the ZIP CRC and uncompressed
length. `acquisition.json` records SHA-256 and sizes for the prepared files.
The acquired dataset is approximately 7.8 MiB, excluding the reusable 108 MiB
download cache; the largest cache items are supplied COLMAP camera/point data.

The source views use an OpenCV fisheye camera. Brush 0.3.0's
[Nerfstudio importer](https://github.com/ArthurBrussee/brush/blob/v0.3.0/crates/brush-dataset/src/formats/nerfstudio.rs)
does not apply distortion. The acquisition script therefore uses the measured
fisheye calibration with OpenCV to produce pinhole images at 752 × 500 and updates
the focal lengths/principal point explicitly. Training uses a maximum long edge
of 512. Feeding distorted source images directly to this Brush release would
silently use the wrong camera model; the adapter rejects such inputs.

The input has 359 supplied poses and 165,875 sparse points. The selected 40 poses
are preserved. A single rigid transform between COLMAP and Nerfstudio coordinates
is derived from a matching camera, then checked against **all 359** supplied
cameras before converting the sparse points. The measured maximum matrix
disagreement was `5.329070518200751e-15`. `source-transforms.json` preserves the
original metadata; no poses or points are invented.

## Backend and artifact boundary

Brush owns optimization and PLY export. `scripts/reconstruct.py` invokes its real
CLI, captures stdout/stderr, records elapsed time and `/usr/bin/time -l` output,
and preserves failure/cancellation status in `job.json`. SIGINT or SIGTERM is
forwarded to the process group. `training.log`, `resources.txt`, `brush-help.txt`
and partial exports remain after failure. A nonzero backend exit or malformed PLY
cannot produce a successful job.

For another local posed dataset, provide:

```text
dataset/
  images/...
  transforms.json       # Nerfstudio/OpenGL camera-to-world matrices + pinhole calibration
  provenance.json       # sourceType, sourceUrl, license, licenseUrl, attribution
  init.ply              # optional measured point cloud, referenced by ply_file_path
  LICENSE               # source data license, copied into the artifact when present
```

The adapter checks finite right-handed rigid camera poses, positive image/focal
calibration, local image paths, source URLs without credentials, provenance fields,
nonblank world identity and absence of distortion before launching Brush. Extra
dataset provenance fields remain input metadata and are omitted from the strict
version-1 world manifest. Use `--title` and `--id`
to identify a different dataset. The raw-image route in [COLMAP.md](COLMAP.md)
produces this dataset layout from actual CPU-estimated cameras.

The world artifact is `world.json`, `scene.ply`, `cameras.json` and source license.
The PLY stays in the backend's exported frame. Its manifest explicitly rotates
the average supplied camera-up vector onto world +Y. **This estimates a useful
viewing orientation, not gravity.** Scale remains arbitrary. The first supplied
camera provides the starting position, forward, up and vertical field of view.
Orbit focus distance uses the median camera baseline; it is a navigation choice,
not a measured surface. Camera matrices in `cameras.json` are transformed into
the same canonical right-handed Y-up frame, with OpenGL −Z camera forward.
There is no floor, collision mesh, safe walking claim or invented path.

## Limitations and next steps

The first training is deliberately short and uses 40 low-resolution views;
unseen surfaces, distant background and incomplete coverage can remain poor.
It is a functional reconstruction experiment, not a fidelity benchmark. Improve
camera overlap and registration before increasing dataset scale. Use a new job
directory to compare longer training or more views, and retain browser evidence
for each artifact. An original short pedestrian recording is the next milestone,
after the documented M0/M1 checks; it was not silently included in this work.
